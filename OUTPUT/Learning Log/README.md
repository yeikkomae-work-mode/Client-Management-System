# Learning Log

**Owner:** `cto` agent · **Created:** 2026-08-25

One file per session where Eikko learns or evaluates something — usually weekends. Same pattern as `OUTPUT/End-of-Day Reports/`, but for skill and tool development rather than client work.

**Naming:** `YYYY-MM-DD.md` — one per day, appended if there's more than one session.

**Purpose:** weekends spent on YouTube, newsletters, and tool discovery currently leave no trace. This is the trace. The Tech Radar holds *verdicts*; this holds the *session* — what was watched, what was ignored, what's still open.

## Template

```markdown
# Learning Log — YYYY-MM-DD

## Reviewed
What was watched/read/tested. Source, and the actual technique — not the video title.

## Kept
What survived the four criteria, and where it went (radar row, PRD, skill note).

## Rejected
What failed and which criterion killed it. This matters as much as what was kept — it's what stops re-litigation.

## Open threads
Unfinished evaluations, things needing a transcript, questions for next session.

## Radar changes
Rows added or superseded in `RESOURCES/Tech Radar.md`.
```

## Rules

- Written by the `cto` agent during or at the end of a session — not reconstructed later from memory.
- A session where nothing survived is still worth logging. "Watched 3 videos, all pitched $99/mo tools that displace nothing" is a useful record.
- Don't duplicate the radar here. Radar = the standing verdict. Log = what happened that day.
