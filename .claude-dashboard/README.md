# Central Command Dashboard

A CRM-style live overview of the Client-Management-System: your profile,
clients (role, tenure, rate), agents, skills/commands, and project pipeline
status — with a Notion link as the home base.

## Layout

Sidebar navigation with six views, plus a top bar with search and your
identity chip:

- **Profile** — a time-aware greeting ("Good morning/afternoon/evening"),
  KPI tiles that jump to the relevant view when clicked and show a **real
  week-over-week trend** (▲/▼ vs. the count from ~7 days ago, sourced from
  `history.json` — shows "building history…" honestly until there's enough
  history to compare, never a fabricated delta), a **weekly activity chart**
  (real count of End-of-Day log entries per day, across all clients), a
  **pipeline health ring** (% of pipeline items that are Active, with a
  legend), a **mini calendar** (current month, real days-with-EOD-activity
  highlighted — no invented events), a mini client list, a **live "next
  auto-refresh" countdown** card, and the Notion home-base card.
- **Clients** — a clickable list; each client opens a detail panel showing
  status, role, commitment/hours, regular meeting (if one is documented),
  how long you've worked together (with the actual source of that date — a
  declared coverage period, a declared start date, or the earliest EOD log
  on file — never guessed), and in the local version only: rate, pay type,
  and a **per-client kanban board** (To Do / Done) built from that client's
  matched task-list file(s) in `PROJECTS/` — real checkbox items pulled
  straight from the file, not invented columns or statuses.
- **Tasks** (new) — every client's tasks in one place, with All / To Do /
  Done tabs and a colored client tag per row. Local version only, same
  reasoning as the per-client kanban.
- **Agents**, **Skills**, **Pipeline** — same content as before, restyled.

**Search** (top bar, or press `/`) filters clients, agents, skills, and
tasks live as you type.

A light/dark toggle lives at the bottom of the sidebar (defaults to light).
Your choice is remembered per-browser via `localStorage`.

### How client → task-file matching works

`scan.py` matches each client to files under `PROJECTS/**` by filename or
first heading, using name tokens unique to that client (first names shared
by multiple clients, like the three "Chris"es, are dropped from matching so
they don't cross-contaminate each other's boards — only surname/nickname
tokens like "Caffera", "Drew", "Starfix" are used for those). Only files
that actually contain `- [ ]` / `- [x]` checkboxes contribute cards — design
docs and notes are matched for reference but don't inject fake tasks.

## On "total salary earned"

There's no real ledger of cumulative earnings anywhere in this system yet —
`OUTPUT/Monthly Reports/*.md` and `OUTPUT/Data & Metrics/Salary & Income
Tracking.md` are blank templates with `$_____` placeholders, not filled-in
records. Rather than invent a number, the client detail panel shows the
client's **rate** (from their profile) and says plainly that lifetime
earnings aren't tracked yet. Once `billing-auditor` produces real monthly
income reports, `scan.py` can be extended to sum them — ask for that when
there's real data to sum.

## Files

- `central-command.html` — the dashboard you actually use. Open it directly in
  your browser (double-click, or drag into a tab). It loads `dashboard-data.js`
  and re-loads it every 60 seconds, so leaving the tab open keeps it fresh.
- `dashboard-data.js` / `dashboard-data.json` — generated data, do not hand-edit.
  Regenerated by `scan.py`.
- `history.json` — one row per day of KPI counts (clients, active clients,
  agents, active pipeline tasks), appended to on every scan. This is what
  powers the real trend badges — delete it if you ever want to reset the
  trend history (the dashboard just goes back to "building history…").
- `scan.py` — scans the filesystem and rewrites the data files.
- `central-command-hosted.html` — a snapshot version with data baked in, used
  to publish as a shareable Claude Artifact. Differs from the local version:
  client folder entries are plain text labels (not clickable — a hosted page
  can't reach your local disk), local file paths are stripped, and **rate,
  pay-type, earnings, regular-meeting, and task-board fields are removed
  from the data entirely** (not just hidden with CSS) so a shared link never
  leaks financial or task-level business detail. Regenerate + republish this
  manually when you want an updated snapshot shared elsewhere — it does not
  auto-refresh like the local version.

## How the auto-refresh works

- A `launchd` job (`com.eikko.centralcommand.scan`, installed at
  `~/Library/LaunchAgents/com.eikko.centralcommand.scan.plist`) runs
  `scan.py` every 15 minutes in the background, rewriting the data files.
- The open dashboard tab re-loads those data files every 60 seconds, so
  within ~15 minutes of any change (new client file, new agent, project moved
  between pipeline folders) it shows up without you doing anything.
- Local `file://` fetch of a sibling JSON file is blocked by CORS in Chrome
  and Safari, so the dashboard loads data via a `<script src="dashboard-data.js">`
  tag instead of `fetch()` — that's why there are both a `.json` and a `.js`
  copy of the same data.

### Manual refresh

Click "refresh now" in the dashboard footer, or re-run the scan yourself:

```bash
python3 "/Users/eikkoyu/Claude Code:Cowork/Client-Management-System/.claude-dashboard/scan.py"
```

### Checking / managing the scheduled job

```bash
# check it's loaded
launchctl list | grep centralcommand

# see recent scan output
cat "/Users/eikkoyu/Claude Code:Cowork/Client-Management-System/.claude-dashboard/logs/scan.out.log"

# stop it
launchctl unload ~/Library/LaunchAgents/com.eikko.centralcommand.scan.plist

# restart it
launchctl load ~/Library/LaunchAgents/com.eikko.centralcommand.scan.plist
```

To remove it entirely: `launchctl unload` it, then delete
`~/Library/LaunchAgents/com.eikko.centralcommand.scan.plist`.

## Adding things so they show up

- **New client** → drop a `[Name] - Profile.md` file in `CLIENT PROFILES/`.
- **New agent** → add a `.md` file with `name:`/`description:` frontmatter in
  `.claude/agents/`.
- **New skill/command** → add a file to `SKILLS/`, or a `.md` with
  `description:` frontmatter in `.claude/commands/`.
- **Project pipeline** → move/add files under `PROJECTS/{Active,In-Progress,
  Pending,Done,Failed,Prospective}/`.

All of these get picked up on the next scan (within 15 min, or immediately
via manual refresh).

## Notion link

The "Open Notion" button points at your Back Office Agents central command
page. To change it, edit the `window.__NOTION_URL__` line near the top of
`central-command.html` (and re-generate `central-command-hosted.html` if you
want the hosted version updated too).
